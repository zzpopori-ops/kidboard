# 오늘의 할 일 (kidboard)

부모가 그날그날의 숙제를 넣고, 아이는 확인하고 체크만 하는 태블릿용 웹앱.
만드는 과정을 처음부터 밟아보고 싶다면 `../HANDS_ON.md` 를 참고하되, 그
문서는 **v1(요일 반복 습관 보드) 스냅샷**이라 지금 코드와 다르다 — 문서
맨 위 안내문 참고. 지금 코드가 실제로 무엇을 하는지는 이 README 와
`docs/superpowers/specs/2026-09-12-homework-sync-design.md` 가 진실이다.

**앱 주소 — https://zzpopori-ops.github.io/kidboard/**

태블릿 Chrome 으로 한 번 열고 홈 화면에 추가하면, 그 뒤로는 인터넷이
없어도 열린다. 맥북이 꺼져 있어도 무관하다.

## 지금 이 앱이 하는 일

- **아이는 1명**. 앱을 켜면 아이 선택 화면 없이 바로 할 일 화면이 뜬다.
  둘째를 추가하는 순간 선택 화면이 저절로 돌아온다 — 아이가 1명일 때만
  건너뛰는 것뿐이라 특별한 분기를 만들지 않았다.
- **숙제는 부모가 그날그날 넣는 날짜 있는 항목**이다("수학 문제집
  1~5쪽"). 요일 반복으로는 표현이 안 되는 것들이라 습관과 다른 자료형으로
  뒀다. 못 끝낸 숙제는 다음날로 넘어가면서 "어제" / "N일 전" 배지가 붙는다.
- **아이 화면에는 숙제가 최대 4개까지만** 보인다. 그 중에서도 **오늘 낸
  것부터 채우고, 남는 자리를 가장 오래 밀린 것으로 채운다.** 밀린 게
  아무리 많아도(예: 9개) 오늘 낸 숙제가 뒤로 밀려 아예 안 보이는 사고를
  실제로 겪은 뒤 정한 규칙이다 — 부모가 방금 넣은 숙제가 아이에게 안
  닿으면 앱을 쓸 이유가 없다. 5번째부터는 **개수도, 힌트도 없이** 그냥
  안 보인다 — "다 하면 끝"이 보여야 아이가 부담을 느끼지 않는다. 부모
  화면에서는 밀린 것까지 전부 보인다.
- **반복되는 집안일("이 닦기")은 습관**이다. 숙제와 성격이 달라(요일마다
  반복, 매번 같은 내용) 작은 칩으로, 요일 필터를 걸어 숙제보다 시각적으로
  덜 도드라지게 보여준다.
- **별은 저장하지 않고 그때그때 계산한다**(`starsOf`). 끝낸 숙제 수(개당
  1개) + 끝낸 습관들의 별 + 보너스 − 교환, 그리고 0 밑으로는 내려가지
  않게 자른다. 마이너스 보너스도 클램프해서, 화면에 안 보이는 "빚"이 쌓일
  수 없게 했다. 이렇게 계산으로만 두는 이유는 Phase 2(집 안 동기화)가
  들어오면 여러 기기의 가변 카운터가 가장 먼저 어긋나기 때문이다 — 계산된
  값은 애초에 어긋날 상태가 없다.
- **템플릿**("수학 문제집 {}~{}쪽")으로 자주 쓰는 숙제를 빈칸만 채워
  추가할 수 있다. `{}` 를 채우지 않고 추가를 누르면 막는다.
- 저장 키는 `kidboard.v2` 다. v1(습관만 있던 시절)에서 자동으로 옮겨오는
  마이그레이션은 없다 — 그때는 실사용자가 없었다.

## 왜 맥북에서 서빙하지 않는가

한때 "맥북에 nginx 컨테이너를 띄우고 태블릿이 `http://맥북이름.local:8080`
으로 붙는" 구성을 검토했다. **성립하지 않는다.** 서비스워커는 보안 컨텍스트
에서만 동작하는데, `localhost` 가 아닌 평문 http 출처는 보안 컨텍스트가
아니기 때문이다. 실측 결과:

| 출처 | isSecureContext | `'serviceWorker' in navigator` |
|---|---|---|
| `http://127.0.0.1:8000` | true | true |
| `http://localhost:8000` | true | true |
| `http://192.168.x.x:8000` | **false** | **false** |
| `http://<이름>.local:8000` | **false** | **false** |

등록이 실패하는 게 아니라 **API 자체가 없다**. 따라서 태블릿에서는
오프라인 캐시도, 홈 화면 추가(standalone)도 불가능하다. 맥북이 잠들면
그 순간 앱이 열리지 않는다.

그래서 배포는 HTTPS 정적 호스팅으로 간다. 맥북은 배포하는 순간에만
필요하고, 그 뒤로는 꺼져 있어도 태블릿이 혼자 동작한다.

`0.0.0.0` 으로 바인드하면 이 막다른 길로 다시 들어가게 되므로 막아뒀다.

## 테스트

처음 한 번만:

```bash
npm install
npx playwright install chromium     # 브라우저 바이너리 (~80MB)
```

이후:

| 명령 | 하는 일 | 걸리는 시간 |
|---|---|---|
| `npm test` | 아래 둘을 순서대로 | 약 15초 |
| `npm run test:unit` | `store.js` 로직만 노드로 검증 (브라우저 없이) | 1초 미만 |
| `npm run test:e2e` | 실제 브라우저로 화면·클릭·저장 검증 | 약 13초 |
| `npm run test:e2e:headed` | 창을 띄워 눈으로 보면서 | |
| `npm run test:e2e:ui` | 타임라인을 오가며 디버깅 | |
| `npm run report` | 마지막 실행의 HTML 리포트 | |

E2E 는 `http-server` 를 자동으로 띄웠다 내린다. 이미 8000 포트에
서버가 떠 있으면 그걸 그대로 쓴다. 포트를 바꾸려면 `PORT=9000 npm run test:e2e`.

**두 테스트의 역할이 다르다.**

- `test/store.test.js` — 별 계산, 숙제 이월·상한 선택, 요일 필터, 백업/복원 같은
  **데이터 규칙**. 빠르니까 코드 고칠 때마다 돌린다.
- `test/e2e.spec.js` (+ `offline.spec.js`, `update.spec.js`) — **브라우저에서만
  드러나는 것**. 실제로 눌리는지, 눌렀을 때 보이는지, 새로고침 후에도 남는지,
  서비스워커가 붙는지, 오프라인에서도 열리는지, 코드를 고치면 한 번에 반영되는지.

둘째가 필요한 이유는 실제로 당해봤기 때문이다. `.modal` 이 `display:grid` 인데
숨김을 `hidden` 속성에만 맡겨서, author 스타일이 UA 스타일을 이겨 `hidden` 이
무력화된 적이 있다. 투명한 모달이 화면 전체를 덮어 **앱이 통째로 먹통**이었는데,
코드 리뷰로도 로직 테스트로도 잡히지 않았다. 눈으로도 옅은 막이라 놓치기 쉽다.
`e2e.spec.js` 의 `[0] 회귀` 가 그 자리를 지킨다 — 닫힌 모달의 computed
`display` 와, 아이 카드에 실제로 손가락이 닿는지를 함께 본다.

기본 PIN은 `1234`. 제목을 1.5초간 길게 누르면 부모 설정으로 들어간다.
첫 실행 후 데이터 탭에서 PIN을 반드시 변경할 것.

## 배포

`main` 에 push 하면 GitHub Actions 가 돈다.

1. **테스트** — 단위(`store.test.js`, assertion 다수) + E2E 29개(화면·오프라인·갱신
   3개 스펙 파일 합계). 하나라도 실패하면 배포하지 않는다
2. **BUILD 치환** — `sw.js` 의 `var BUILD = 'dev';` 를 커밋 해시로 바꾼다.
   손으로 올리지 않는다. 치환됐는지 배포 전에 확인하고, `'dev'` 가 남아 있으면 실패시킨다
3. **배포** — 앱 파일만 올린다(테스트·Dockerfile 은 사이트에 두지 않는다)

PR 은 테스트만 돌고 배포되지 않는다.

## 롤백 — 잘못된 버전이 나갔을 때

앱 코드는 네트워크 우선이라 **배포가 태블릿에 빨리 닿는다. 좋은 것도 나쁜 것도.**
그래서 되돌리는 법을 미리 알아둔다.

```bash
git revert <잘못된 커밋>    # 되돌리는 커밋을 새로 쌓는다. 이력을 지우지 않는다
git push                    # Actions 가 테스트를 다시 돌리고 배포한다
```

`git push --force` 로 이력을 지우지 않는다. 공개 저장소에서 되돌린 기록까지
남기는 편이 나중에 "왜 이렇게 됐지"를 설명해 준다.

더 급하면 Actions 탭에서 **직전에 성공한 실행을 다시 돌려도**(Re-run) 된다.
그쪽이 테스트를 새로 돌리지 않아 몇 분 빠르다.

### 태블릿에 반영되기까지

실측값이다(로컬 측정이라 절대 시간은 집 네트워크에 따라 달라지지만, **몇 번 열어야
하는가**는 그대로다).

| 상황 | 태블릿에 반영되는 시점 | 측정 |
|---|---|---|
| 잘못된 버전 배포 | 앱을 **1번** 열면 | 8ms |
| 롤백 배포 | 앱을 **1번** 열면 | 9ms |
| 태블릿이 오프라인 | 반영 안 됨. **마지막 캐시**로 계속 동작 | 7ms |
| 오프라인이었다가 다시 온라인 | 온라인 상태로 **1번** 열면 | 7ms |

핵심은 **1번**이다. 캐시 우선이던 시절에는 3번 열어야 했고, `sw.js` 버전을
안 올리면 영원히 반영되지 않았다.

### 아직 측정하지 않은 것

**배포된 사이트에서 "고쳐서 배포 → 앱 1회 열기 → 새 코드" 종단 측정 — 미측정.**
사유: 데이터 구조 변경이 예정되어 있어, 지금 재도 곧 다시 재야 한다.

지금까지 확보한 근거는 두 가지다.

- 라이브에서 network-first 가 실제로 동작하는 것은 확인했다. 서비스워커가
  제어 중이고 캐시가 차 있는 상태에서 새로고침해도 `css/style.css`,
  `js/store.js`, `js/views.js`, `js/app.js` 가 네트워크로 나갔다.
  아이콘은 0건(캐시 우선). 이게 1회 반영을 만드는 메커니즘이다
- 종단 동작 자체는 `test/update.spec.js` 가 로컬에서 통과한다

구조를 바꾼 뒤에 라이브에서 다시 측정할 것.

### 3초 타임아웃이 실제로 걸리는 때

`sw.js` 의 `NET_TIMEOUT` 은 3초지만, 대부분의 실패는 3초를 기다리지 않는다.

| 상황 | 첫 화면까지 |
|---|---|
| 서버 정상 | 22ms |
| 서버 죽음(연결 거부) | 39ms — 즉시 실패하므로 타임아웃을 안 기다린다 |
| 네트워크 차단(비행기 모드) | 18ms |

3초가 실제로 소모되는 건 **응답이 오지도 않고 끊기지도 않을 때**다. 예를 들어
와이파이에는 붙었는데 인터넷이 안 되는 공용 와이파이, 신호가 아주 약한 경우.
그때도 3초 뒤엔 캐시로 넘어가 앱이 열린다. 아이를 흰 화면 앞에 세워두지 않기
위한 상한이다.

### 오프라인인 태블릿에 급히 반영해야 한다면

방법이 없다. 그 기기가 온라인이 되어야 한다. 이건 오프라인 우선 앱의
구조적 대가이고, 대신 맥북이 꺼져 있어도 앱이 동작하는 것을 얻었다.

## 맥북 운영 — 동기화 서버가 도는 조건

동기화 서버는 맥북의 Docker 컨테이너(`sync`)에서 돈다. 맥북이 깨어 있어야
PC와 태블릿이 데이터를 주고받는다.

### 전제: 클램쉘 모드

이 집의 맥북은 **뚜껑을 닫은 채(클램쉘) 외부 디스플레이와 전원을 연결해서**
쓴다. 그 상태에서는 뚜껑을 닫아도 잠들지 않으므로 **절전 방지 도구가 필요 없다.**

2026-09-19 실측:

```
전원            AC Power (연결됨)
외부 디스플레이   연결됨
AC 유휴 슬립     sleep 0  (잠들지 않음)
컨테이너         sync running
ping            {"ok":true,"seq":2}
```

`caffeinate` 같은 절전 방지 도구는 쓰지 않는다. 검토했다가 필요 없어서 접었다.

### ⚠️ 클램쉘이 깨지는 조건 — 동기화가 안 되면 여기부터 의심한다

아래 중 하나라도 해당되면 뚜껑을 닫는 순간 맥북이 잠들고, **잠든 동안에는
동기화가 멈춘다.**

| 상황 | 결과 |
|---|---|
| 외부 디스플레이를 뽑았다 | 뚜껑 닫으면 잠든다 |
| 전원 어댑터를 뺐다(배터리) | 뚜껑 닫으면 잠든다. 배터리에서는 유휴 슬립도 켜져 있다 |
| 외부 디스플레이가 절전으로 꺼졌다 | 기종·설정에 따라 잠들 수 있다 |
| 맥북을 들고 나갔다 | 같은 와이파이가 아니므로 애초에 안 된다 |

**잠들어도 데이터는 안전하다.** 아이가 체크한 별은 태블릿 큐에 쌓였다가 맥북이
깨어나면 저절로 올라간다. 아이 화면은 맥북 상태와 무관하게 평소대로 동작한다.
멈추는 것은 기기 사이 전달뿐이다.

### 동기화가 안 될 때 확인 순서

1. **맥북이 깨어 있나** — 위의 클램쉘 조건을 먼저 본다
2. **컨테이너가 도나** — `docker compose ps sync` 가 `running` 인지
3. **서버가 응답하나** — `curl -s https://<맥북이름>.local:8443/api/ping`
   → `{"ok":true,"seq":N}` 가 나와야 한다
4. **기기에서 응답하나** — 문제가 있는 기기의 브라우저로 같은 주소를 연다
   - 인증서 경고가 뜬다 → 그 기기에 CA 가 설치되지 않았다
   - 아무것도 안 뜬다 → 같은 와이파이가 아니거나 맥북이 잠들었다
5. **앱이 뭐라고 하나** — 부모 설정 → 데이터 탭 → `지금 동기화`.
   실패 메시지가 원인별로 다르게 나온다(토큰/주소/미초기화/연결불가)

컨테이너 로그: `docker compose logs sync --tail 50`
서버가 가진 데이터: `server/data/state.json`

## 컨테이너에서 테스트

컨테이너는 **테스트 실행 환경일 뿐**이고 앱을 서빙하지 않는다.
맥에 Node 나 브라우저를 깔지 않아도, 또 맥 환경이 바뀌어도 같은 결과를 얻으려면:

실행법이 두 가지다. **언제 무엇을 쓰는지가 중요하다.**

| 명령 | 무엇을 검사하나 | 언제 |
|---|---|---|
| `docker compose run --rm e2e` | **지금 작업 중인 파일** (소스가 마운트됨) | 개발 중. 코드 고치고 바로 돌릴 때 |
| `docker compose run --rm --build e2e` | **이미지에 구워진 파일** (재빌드 후 고정) | CI·릴리스 전. 재현 가능한 결과가 필요할 때 |

소스(`css`, `js`, `index.html`, `sw.js`, `manifest.webmanifest`, `icons`,
`test`, `playwright.config.js`)는 읽기 전용으로 마운트된다. 그래서 첫 번째 명령은
재빌드 없이 방금 고친 코드를 검사한다.

`package.json` / `package-lock.json` 은 **일부러 마운트하지 않았다.** 의존성이
바뀌면 `npm ci` 를 다시 돌려야 하므로 그때는 `--build` 가 맞다.

> 마운트가 없던 시절엔 코드를 고치고 컨테이너를 돌려도 **빌드 시점의 낡은 소스**가
> 검사됐다. 초록불을 보고 깨진 코드를 내보낼 수 있는 구조였다. 지금은 위 표의
> 첫 줄이 작업 트리를 본다.

이미지 태그는 `v1.56.1-noble` 로 못박혀 있다. `package.json` 의
`@playwright/test` 버전과 **반드시 같아야** 한다. 둘이 어긋나면 러너가
이미지에 미리 깔린 브라우저를 못 찾고 실행 시점에 새로 받으려 든다.
올릴 때는 `package.json` 과 `Dockerfile` 을 **함께** 올린다.

### 호스트 / 컨테이너 대조 (2026-09-12 실측)

| | 맥북 (호스트) | 컨테이너 |
|---|---|---|
| OS | macOS 26.6.2 | Ubuntu 24.04.3 LTS |
| Arch | arm64 | aarch64 |
| Node | **v26.0.0** | **v22.20.0** |
| Playwright | 1.56.1 | 1.56.1 |
| Chromium | 141.0.7390.37 | 141.0.7390.37 |

**Chromium 은 양쪽이 같다.** 브라우저 버전은 Playwright 버전에 묶여 있어서,
`@playwright/test` 를 고정한 시점에 이미 통제되고 있었다. 즉 도커가 잡아주는
것은 브라우저가 아니라 **그 바깥** — OS, 시스템 라이브러리, 폰트, 그리고
위 표에서 실제로 4 버전이나 벌어진 Node 다.

나중에 스크린샷 비교(시각 회귀)를 넣는다면 폰트 렌더링이 OS 마다 달라서
기준 이미지는 **반드시 컨테이너에서** 만들어야 한다.

## 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 셸. 스크립트 로드 순서가 의존 순서 |
| `css/style.css` | 디자인 토큰 + 두 가지 타일 모드 |
| `js/store.js` | 데이터. localStorage를 만지는 유일한 파일. 숙제·습관·별 계산이 전부 여기 있다 |
| `js/ui.js` | 토스트·모달·PIN 키패드·효과음·별 연출 |
| `js/views.js` | 아이 화면 (숙제 카드 + 습관 칩 + 상점) |
| `js/admin.js` | 부모 설정 (숙제·아이·습관·보상·데이터) |
| `js/app.js` | 화면 전환, 클릭 위임, 자정 감지 |
| `sw.js` | 오프라인 캐시. 앱 코드는 네트워크 우선, 아이콘은 캐시 우선 |
| `test/store.test.js` | 데이터 규칙 검증 (노드) |
| `test/e2e.spec.js` | 화면·조작 검증 (Playwright) |
| `test/offline.spec.js` | 서버가 죽어도 캐시만으로 열리는지 검증 |
| `test/update.spec.js` | 코드를 고치면 한 번에 반영되는지 검증 |
| `playwright.config.js` | E2E 설정. 테스트용 서버를 자동으로 띄운다 |
| `Dockerfile` / `compose.yaml` | 테스트 실행 환경 고정 |
| `.github/workflows/deploy.yml` | 테스트 게이트 + 배포. `docs/` 는 배포물에 포함하지 않는다 |
| `docs/superpowers/` | 설계 스펙·계획 문서. 배포되지 않는, 저장소 안에서만 보는 기록 |
