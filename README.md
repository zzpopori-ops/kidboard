# 오늘의 할 일 (kidboard)

부모가 할 일을 정리하고, 아이는 확인하고 체크만 하는 태블릿용 웹앱.
만드는 과정과 설계 이유는 `HANDS_ON.md` 참고.

## 빠른 시작

```bash
npm install          # 최초 1회
npm run serve        # http://localhost:8000
```

VS Code 라면 `index.html` 우클릭 → Open with Live Server 도 된다.

`npm run serve` 는 **127.0.0.1 에만** 바인드한다. 일부러 그렇게 했다.
아래를 읽을 것.

## 왜 맥북에서 서빙하지 않는가

한때 "맥북에 nginx 컨테이너를 띄우고 태블릿이 `http://맥북이름.local:8080`
으로 붙는" 구성을 검토했다. **성립하지 않는다.** 서비스워커는 보안 컨텍스트
에서만 동작하는데, `localhost` 가 아닌 평문 http 출처는 보안 컨텍스트가
아니기 때문이다. 실측 결과:

| 출처 | isSecureContext | `'serviceWorker' in navigator` |
|---|---|---|
| `http://127.0.0.1:8000` | true | true |
| `http://localhost:8000` | true | true |
| `http://192.168.x.x:8000` | **false** | **false** |
| `http://<이름>.local:8000` | **false** | **false** |

등록이 실패하는 게 아니라 **API 자체가 없다**. 따라서 태블릿에서는
오프라인 캐시도, 홈 화면 추가(standalone)도 불가능하다. 맥북이 잠들면
그 순간 앱이 열리지 않는다.

그래서 배포는 HTTPS 정적 호스팅으로 간다. 맥북은 배포하는 순간에만
필요하고, 그 뒤로는 꺼져 있어도 태블릿이 혼자 동작한다.

`0.0.0.0` 으로 바인드하면 이 막다른 길로 다시 들어가게 되므로 막아뒀다.

## 테스트

처음 한 번만:

```bash
npm install
npx playwright install chromium     # 브라우저 바이너리 (~80MB)
```

이후:

| 명령 | 하는 일 | 걸리는 시간 |
|---|---|---|
| `npm test` | 아래 둘을 순서대로 | 약 15초 |
| `npm run test:unit` | `store.js` 로직만 노드로 검증 (브라우저 없이) | 1초 미만 |
| `npm run test:e2e` | 실제 브라우저로 화면·클릭·저장 검증 | 약 13초 |
| `npm run test:e2e:headed` | 창을 띄워 눈으로 보면서 | |
| `npm run test:e2e:ui` | 타임라인을 오가며 디버깅 | |
| `npm run report` | 마지막 실행의 HTML 리포트 | |

E2E 는 `http-server` 를 자동으로 띄웠다 내린다. 이미 8000 포트에
서버가 떠 있으면 그걸 그대로 쓴다. 포트를 바꾸려면 `PORT=9000 npm run test:e2e`.

**두 테스트의 역할이 다르다.**

- `test/store.test.js` — 별 증감, 요일 필터, 연속일, 백업/복원 같은 **데이터 규칙**.
  빠르니까 코드 고칠 때마다 돌린다.
- `test/e2e.spec.js` — **브라우저에서만 드러나는 것**. 실제로 눌리는지, 눌렀을 때
  보이는지, 새로고침 후에도 남는지, 서비스워커가 붙는지.

둘째가 필요한 이유는 실제로 당해봤기 때문이다. `.modal` 이 `display:grid` 인데
숨김을 `hidden` 속성에만 맡겨서, author 스타일이 UA 스타일을 이겨 `hidden` 이
무력화된 적이 있다. 투명한 모달이 화면 전체를 덮어 **앱이 통째로 먹통**이었는데,
코드 리뷰로도 로직 테스트로도 잡히지 않았다. 눈으로도 옅은 막이라 놓치기 쉽다.
`e2e.spec.js` 의 `[0] 회귀` 가 그 자리를 지킨다 — 닫힌 모달의 computed
`display` 와, 아이 카드에 실제로 손가락이 닿는지를 함께 본다.

기본 PIN은 `1234`. 제목을 1.5초간 길게 누르면 부모 설정으로 들어간다.
첫 실행 후 데이터 탭에서 PIN을 반드시 변경할 것.

## 컨테이너에서 테스트

컨테이너는 **테스트 실행 환경일 뿐**이고 앱을 서빙하지 않는다.
맥에 Node 나 브라우저를 깔지 않아도, 또 맥 환경이 바뀌어도 같은 결과를 얻으려면:

실행법이 두 가지다. **언제 무엇을 쓰는지가 중요하다.**

| 명령 | 무엇을 검사하나 | 언제 |
|---|---|---|
| `docker compose run --rm e2e` | **지금 작업 중인 파일** (소스가 마운트됨) | 개발 중. 코드 고치고 바로 돌릴 때 |
| `docker compose run --rm --build e2e` | **이미지에 구워진 파일** (재빌드 후 고정) | CI·릴리스 전. 재현 가능한 결과가 필요할 때 |

소스(`css`, `js`, `index.html`, `sw.js`, `manifest.webmanifest`, `icons`,
`test`, `playwright.config.js`)는 읽기 전용으로 마운트된다. 그래서 첫 번째 명령은
재빌드 없이 방금 고친 코드를 검사한다.

`package.json` / `package-lock.json` 은 **일부러 마운트하지 않았다.** 의존성이
바뀌면 `npm ci` 를 다시 돌려야 하므로 그때는 `--build` 가 맞다.

> 마운트가 없던 시절엔 코드를 고치고 컨테이너를 돌려도 **빌드 시점의 낡은 소스**가
> 검사됐다. 초록불을 보고 깨진 코드를 내보낼 수 있는 구조였다. 지금은 위 표의
> 첫 줄이 작업 트리를 본다.

이미지 태그는 `v1.56.1-noble` 로 못박혀 있다. `package.json` 의
`@playwright/test` 버전과 **반드시 같아야** 한다. 둘이 어긋나면 러너가
이미지에 미리 깔린 브라우저를 못 찾고 실행 시점에 새로 받으려 든다.
올릴 때는 `package.json` 과 `Dockerfile` 을 **함께** 올린다.

### 호스트 / 컨테이너 대조 (2026-09-12 실측)

| | 맥북 (호스트) | 컨테이너 |
|---|---|---|
| OS | macOS 26.6.2 | Ubuntu 24.04.3 LTS |
| Arch | arm64 | aarch64 |
| Node | **v26.0.0** | **v22.20.0** |
| Playwright | 1.56.1 | 1.56.1 |
| Chromium | 141.0.7390.37 | 141.0.7390.37 |

**Chromium 은 양쪽이 같다.** 브라우저 버전은 Playwright 버전에 묶여 있어서,
`@playwright/test` 를 고정한 시점에 이미 통제되고 있었다. 즉 도커가 잡아주는
것은 브라우저가 아니라 **그 바깥** — OS, 시스템 라이브러리, 폰트, 그리고
위 표에서 실제로 4 버전이나 벌어진 Node 다.

나중에 스크린샷 비교(시각 회귀)를 넣는다면 폰트 렌더링이 OS 마다 달라서
기준 이미지는 **반드시 컨테이너에서** 만들어야 한다.

## 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 셸. 스크립트 로드 순서가 의존 순서 |
| `css/style.css` | 디자인 토큰 + 두 가지 타일 모드 |
| `js/store.js` | 데이터. localStorage를 만지는 유일한 파일 |
| `js/ui.js` | 토스트·모달·PIN 키패드·효과음·별 연출 |
| `js/views.js` | 아이 화면 (선택 / 할 일 / 상점) |
| `js/admin.js` | 부모 설정 (아이·할 일·보상·데이터) |
| `js/app.js` | 화면 전환, 클릭 위임, 자정 감지 |
| `sw.js` | 오프라인 캐시. 수정 시 `kidboard-v1` 버전을 올릴 것 |
| `test/store.test.js` | 데이터 규칙 검증 (노드) |
| `test/e2e.spec.js` | 화면·조작 검증 (Playwright) |
| `playwright.config.js` | E2E 설정. 테스트용 서버를 자동으로 띄운다 |
| `Dockerfile` / `compose.yaml` | 테스트 실행 환경 고정 |

## 주의

- 코드를 고쳐도 태블릿에 반영되지 않으면 `sw.js`의 캐시 이름을 올렸는지 확인
- 데이터는 해당 브라우저에만 저장됨. 부모 설정 → 데이터 → 백업 내보내기로 주기적 백업
