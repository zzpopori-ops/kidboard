# 숙제 보드 + 집 안 동기화 — 설계

작성일 2026-09-12 · 상태: 설계 확정, 구현 전

> 이 문서에서 `<맥북이름>.local` 과 `<맥북IP>` 는 자리표시자다. 실제 값은
> 저장소에 넣지 않는다 (공개 저장소이므로). 각자 환경의 값은 로컬 메모에 둔다.

---

## 1. 왜 바꾸는가

지금 앱은 "요일마다 반복하는 습관"을 체크하는 도구다. 실제로 필요한 것은
**부모가 날짜마다 넣어주는 그날의 숙제**다. "수학 문제집 1~5쪽" 같은 것은
매주 같지 않으므로 요일 반복으로 표현할 수 없다.

그리고 숙제는 부모가 **PC와 태블릿 양쪽에서** 넣을 수 있어야 한다. 지금
데이터는 `localStorage` 에만 있고 — 앱 전체에 네트워크 호출이 한 줄도 없다 —
`localStorage` 는 기기마다 완전히 분리된다. **PC에서 넣은 숙제는 PC에만 남고
태블릿에 영원히 가지 않는다.** 이건 기능 추가가 아니라 저장 계층을 새로
만드는 일이다.

## 2. 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 아이 수 | 첫째 1명. 앱 켜면 바로 할 일 화면 | `children.length === 1` 이면 선택 화면을 건너뛴다. 둘째를 추가하면 선택 화면이 저절로 돌아온다 — 특별 분기를 만들지 않는다 |
| 습관 | **유지**. 숙제와 공존 | 성격이 다르므로 다른 종류로 분리한다 |
| 숙제 입력 시점 | 그때그때 불규칙 | 동기화 지연이 짧아야 한다 |
| 미완료 숙제 | 다음날로 이월, 밀렸다고 표시 | |
| 아이 화면 상한 | **숙제 4개까지**. 5번째부터는 아이에게 보이지 않음 | "다 하면 끝"이 보여야 한다. "대기 3개" 같은 표시도 아이 화면에 두지 않는다 — 끝이 보이게 하려는 의도를 스스로 깨기 때문 |
| 별 | 숙제당 고정 1개. 습관은 기존대로 1~3 | 입력 부담 최소화 |
| 별 보관 | **저장하지 않고 계산** | 동기화가 들어오면 가변 카운터가 가장 먼저 틀어진다 |
| 타이핑 | 템플릿 + 빈칸 채우기 | |
| 앱 배달 | GitHub Pages (HTTPS) | 맥북과 무관하게 아이 화면이 항상 열린다 |
| 데이터 | 맥북 Docker (집 LAN) | 숙제 내용이 집 밖으로 나가지 않는다 |
| 집 밖 사용 | 하지 않음 | 터널 없음 |
| streak | 보류 | 숙제 기반에서 "연속" 정의가 모호하다. 필요해지면 그때 기준을 정한다 |

## 3. 아키텍처

```
  GitHub Pages (HTTPS)              맥북 (집 LAN, Docker)
  https://<계정>.github.io/kidboard/  https://<맥북이름>.local:8443
  ┌──────────────────────────┐      ┌──────────────────────────┐
  │ 앱 (HTML/JS/CSS)          │      │ 동기화 API + 데이터 파일  │
  │ 서비스워커 캐시            │─────▶│ restart: unless-stopped  │
  │ localStorage (로컬 우선)   │◀─────│ mkcert 인증서             │
  │ 작업 큐 (outbox)          │      └──────────────────────────┘
  └──────────────────────────┘
        ▲              ▲
     태블릿           PC            둘 다 같은 URL, 같은 코드
```

**앱 배달과 데이터 동기화를 분리한 것이 이 설계의 핵심이다.** 맥북이 꺼져
있어도 앱은 서비스워커 캐시로 열리고, 아이는 평소대로 체크한다. 동기화만
멈춘다.

### 왜 앱을 맥북에서 서빙하지 않는가

서비스워커는 보안 컨텍스트에서만 동작한다. 실측 결과:

| 출처 | isSecureContext | `'serviceWorker' in navigator` |
|---|---|---|
| `https://<계정>.github.io/...` | true | true |
| `http://<맥북IP>:8000` | **false** | **false** |
| `http://<맥북이름>.local:8000` | **false** | **false** |

평문 http 로 서빙하면 서비스워커 API 가 **아예 존재하지 않는다.** 오프라인도
홈 화면 추가도 불가능하다.

맥북에서 HTTPS(mkcert)로 서빙하면 이 문제는 풀리지만, **인증서가 만료되는
날 아이가 앱을 못 연다.** 출처도 `.local` 이름에 영구히 묶여, 나중에 맥북을
바꾸면 모아둔 별이 사라진다. 그래서 앱은 Pages 에 두고 출처를 고정한다.

### 공개 출처에서 집 LAN 을 부르려면 (실측)

Chromium 141 기준:

```
인증서신뢰=O  권한허용=O  ->  HTTP 200
인증서신뢰=O  권한허용=X  ->  실패 (Permission was denied)
인증서신뢰=X  권한허용=O  ->  실패
인증서신뢰=X  권한허용=X  ->  실패
```

- HTTPS 페이지에서 `http://` 를 부르면 **혼합 콘텐츠로 차단**된다
- HTTPS 로 바꿔도 **Private Network Access** 가 한 번 더 막는다
- 서버가 보내는 `Access-Control-Allow-Private-Network` 헤더는 **영향이 없다**.
  이제 서버가 허락하는 방식이 아니라 사용자가 권한을 허용하는 모델이다

따라서 태블릿에서 **한 번만** 두 가지를 해야 한다: mkcert 루트 CA 설치,
로컬 네트워크 접근 권한 허용. 2026-09-12 실기기에서 통과를 확인했다.

## 4. 데이터 모델

```
{
  version: 2,
  pin, sound,
  children:  [{ id, name, emoji, color, canRead }],        // stars 없음 — 계산한다
  habits:    [{ id, childId, emoji, label, stars, days:[0..6] }],
  homework:  [{ id, childId, emoji, label, date, stars:1, doneOn }],
  templates: [{ id, emoji, text }],                        // "수학 문제집 {}~{}쪽"
  rewards:   [{ id, emoji, label, cost }],
  progress:  { childId: { 'YYYY-MM-DD': [habitId, ...] } },// 습관 전용
  bonuses:   [{ id, childId, amount, memo, at }],
  redemptions:[{ id, childId, rewardId, label, emoji, cost, at }]
}
```

### 숙제 완료는 항목 자신에 기록한다

습관은 날짜마다 새로 시작하므로 지금처럼 `progress[아이][날짜]` 에 둔다.
숙제는 다르다. 9/14 에 낸 숙제를 9/16 에 끝낼 수 있어야 하므로 완료를
항목에 `doneOn: 'YYYY-MM-DD'` 로 붙인다.

그러면 오늘 보여줄 숙제가 한 줄로 정의된다.

```
date <= 오늘  AND  doneOn 이 비어 있음
```

`date < 오늘` 이면 밀린 것이다. **이월 처리 코드도 자정 배치도 필요 없다.**
진행 기록을 날짜 키 아래 두어 자정 리셋 코드를 없앴던 것과 같은 수법이다.

### 아이 화면에 보여줄 숙제 (fix round 1 — 화면을 실제로 그려보고 바꿈)

처음 설계는 종이 위에서 "오래 밀린 것부터 4개"로 정했다. 그런데 실제
화면에 렌더링해서 보니, 밀린 숙제가 쌓여 있으면(예: 9개) 그 오래된 4개가
상한을 다 채워버려서 **오늘 새로 낸 숙제가 화면에 아예 안 뜨는** 상황이
나왔다. 아이 입장에서는 오늘 숙제가 있는데도 안 보이는 것이니, 앱이 있을
이유가 없어지는 셈이다. 그래서 선택 규칙을 오늘 것을 먼저 채우는 쪽으로
바꿨다.

```
오늘분  = 후보 중 date == 오늘
밀린것  = 후보 중 date <  오늘, date 오름차순 (오래 밀린 것 먼저)

노출 = 오늘분 전부 + 밀린것 (남는 자리만큼, 오래된 순)
     → 상한 4개까지만
```

예:
- 오늘 2개 + 밀린 9개 → 오늘 2개 + 밀린 2개(가장 오래된 것부터)
- 오늘 4개 + 밀린 9개 → 오늘 4개만, 밀린 것은 전부 대기
- 오늘 0개 + 밀린 9개 → 밀린 것 중 가장 오래된 4개
- 오늘 6개 + 밀린 0개 → 오늘 것 중 4개 (상한은 그대로)

화면에 놓는 순서도 고른 순서 그대로 — 오늘 것 먼저, 그다음 밀린 것.
"어제" / "N일 전" 뱃지가 이미 밀린 것을 구분해주므로, 위치까지 그 역할을
떠맡을 필요가 없고, 부모가 생각하는 순서("오늘 것 먼저 확인, 밀린 것도
챙기기")와도 맞는다.

나머지는 아이 화면에 **존재하지 않는다.** 개수 표시도 하지 않는다.
부모 화면에서만 "밀린 것 N개"로 보인다. 부모 화면이 쓰는 "밀린 총량"
조회는 이 규칙과 무관하게 상한 없는 오래된순 그대로다 — 상한이 있는
아이 화면용 선택과, 상한 없는 부모 화면용 조회는 서로 다른 함수다.

### 별은 계산한다

```
별 = (doneOn 이 있는 숙제 수 × 1)
   + (progress 에 기록된 습관의 stars 합)
   + (bonuses 의 amount 합)
   − (redemptions 의 cost 합)
```

원본 기록에서 매번 계산하면 **더하다 틀어지는 일이 불가능하다.** 체크를
풀면 별이 회수되는 기존 규칙도 자동으로 성립한다. 동기화에서 같은 기록이
중복 도착해도 별 개수가 흔들리지 않는다 — 방어가 두 겹이다.

**음수 보너스(차감)는 합계가 아니라 기록 자체를 있는 만큼만 남긴다.** 부모가
별 5개를 깎으려 했는데 아이에게 2개뿐이면, 기록되는 값은 -5 가 아니라 -2
다. 합계만 `Math.max(0, n)` 으로 가려 버리면 화면에는 0으로 보이지만
`bonuses` 안에는 -5 가 그대로 남아, 나중에 아이가 별을 벌어도 그 빚부터
갚느라 정작 화면에는 안 나타난다 — 아이 입장에서는 별을 벌었는데도 아무
일도 안 일어난 것처럼 보인다. **아이에게 보이지 않는 상태**는 이 프로젝트가
반복해서 겪은 문제라, 문서로 남겨 조심하는 대신 애초에 그런 기록이 생길
수 없게 한다. 이미 0개인 아이에게서 더 깎으려 하면 기록을 아예 만들지
않는다.

## 5. 화면

### 아이 화면 (앱 진입 기본)

```
🐯 첫째                      [별병]  ⭐12  [상점]
─────────────────────────────────────────────
오늘의 숙제                            (최대 4)
┌─────────┐ ┌─────────┐
│ 📕      │ │ ✏️  어제 │   ← 밀린 것은 뱃지
│ 수학     │ │ 받아쓰기 │
│ 1~5쪽   │ │ 10문제  │
│   ⭐    │ │   ⭐    │
└─────────┘ └─────────┘
─────────────────────────────────────────────
매일 하는 것
[🪥 이 닦기] [🧺 빨래통에 넣기]        ← 작은 칩
```

숙제는 큰 카드, 습관은 작은 칩. 위계가 곧 의미다. 한 덩어리로 섞으면
습관이 "오늘 4개" 예산을 잡아먹어 숙제가 밀려난다.

동기화 상태는 **아이 화면에 절대 표시하지 않는다.**

### 부모 화면 (제목 1.5초 롱프레스 → PIN)

PC와 태블릿이 같은 화면을 쓴다. 별도 앱을 만들지 않는다.

| 탭 | 내용 |
|---|---|
| 숙제 | 날짜 선택(기본 오늘) → 그날 목록 → 템플릿으로 추가. 밀린 것 목록과 "오늘로" 버튼 |
| 습관 | 요일 반복 항목 관리 |
| 보상 | 기존과 동일 |
| 아이 | 이름·이모지·색, 보너스 별 주기(메모 포함) |
| 데이터 | 백업/복원, PIN, 동기화 상태·서버 주소·토큰 |

숙제 입력은 템플릿의 빈칸만 채운다. 별은 자동 1개라 입력할 것이 없다.

## 6. 서버 API

맥북에서 Docker 컨테이너로 돈다. `restart: unless-stopped`.

- 주소: `https://<맥북이름>.local:8443` (폴백 `https://<맥북IP>:8443`)
- 인증: `Authorization: Bearer <토큰>`. 긴 랜덤 문자열 하나를 기기마다 한 번 입력
- CORS: `Access-Control-Allow-Origin: https://<계정>.github.io`
- 저장: 파일 하나 (JSON 또는 SQLite) + 적용한 opId 집합

### GET /api/ping

헬스 체크. 인증 불필요.

```json
{ "ok": true, "seq": 412 }
```

### POST /api/sync

**밀어 올리기와 당겨오기를 한 번에 한다.** 왕복이 하나라 단순하고,
오프라인에서 돌아온 직후에도 한 번에 정리된다.

요청:

```json
{
  "deviceId": "tab-a1b2",
  "since": 400,
  "ops": [
    { "opId": "op-7f3a91", "at": "2026-09-14T08:12:03.120Z",
      "type": "homework.setDone",
      "payload": { "id": "hw-221", "doneOn": "2026-09-14" } }
  ]
}
```

응답:

```json
{
  "seq": 413,
  "accepted": ["op-7f3a91"],
  "state": { "...전체 상태..." }
}
```

- `accepted` 에 들어온 opId 만 클라이언트 큐에서 지운다
- `state` 는 서버가 확정한 전체 상태다. 가족용 규모(수백 건)에서는 델타보다
  전체를 주는 편이 단순하고 버그가 적다. 커지면 `since` 로 델타를 주도록
  바꿀 여지를 남겨둔다

### opId 멱등 처리 — 가장 중요한 부분

서버는 적용한 `opId` 를 전부 기억한다. **이미 본 opId 는 무시하고 accepted
에만 넣어 응답한다.**

```
op 수신
  ├─ opId 를 이미 적용했나? → 예: 아무것도 하지 않고 accepted 에 추가
  └─ 아니오 → 상태에 적용, opId 기록, seq += 1, accepted 에 추가
```

이게 없으면 **응답을 못 받아 재전송할 때마다 별이 늘어난다.** 와이파이가
끊겼다 붙는 상황에서 반드시 일어난다. 아이는 30초 안에 알아챈다.

`opId` 는 클라이언트가 생성한다(기기ID + 시각 + 난수). 재전송해도 **같은
opId 를 그대로** 쓴다 — 새로 만들면 멱등성이 깨진다.

### 충돌

쓰기가 자연스럽게 갈린다.

| 누가 | 무엇을 쓰나 |
|---|---|
| 부모 (PC·태블릿) | 숙제·습관·템플릿·보상 정의 |
| 아이 (태블릿) | 완료 여부, 보상 교환 |

같은 필드를 동시에 고치는 일이 거의 없다. 겹칠 때는 **서버 도착 순서대로
적용(last write wins)** 한다. 별은 계산값이므로 순서가 뒤바뀌어도 합계가
틀어지지 않는다.

## 7. 동기화 프로토콜 (클라이언트)

```
사용자 조작
  → localStorage 에 즉시 반영 (화면은 네트워크를 기다리지 않는다)
  → 작업을 큐(outbox)에 적재
  → 서버에 닿으면 POST /api/sync
       성공: accepted 된 것만 큐에서 제거, 서버 상태로 갱신
       실패: 큐에 그대로 둔다. 다음 기회에 다시 보낸다
```

당겨오는 시점: 앱 시작, `visibilitychange` 로 화면이 다시 보일 때,
그리고 켜져 있는 동안 몇 분 간격. `app.js` 의 자정 감시가 이미 같은 구조라
얹기 좋다.

**아이 화면은 맥북 상태를 모른다.** 맥북이 꺼져 있어도 체크하고, 별이 오르고,
상점에서 교환한다. 전부 로컬에서 일어난다.

## 8. 실패 모드

| 상황 | 아이 화면 | 부모 화면 | 복구 |
|---|---|---|---|
| **맥북 꺼짐/잠듦** | 정상 동작. 체크·별·교환 전부 됨. 큐에 쌓임 | "마지막 동기화: N시간 전" | 맥북을 켜면 큐가 저절로 올라간다 |
| **인증서 만료** (2028년경) | 정상 동작. 동기화만 멈춤 | 동기화 실패 표시 | 같은 CA로 리프 재발급. **태블릿은 손대지 않는다** |
| **로컬 네트워크 권한 초기화** | 정상 동작. 동기화만 멈춤 | 동기화 실패 표시 | 태블릿에서 주소창 자물쇠 → 사이트 설정 → 권한 다시 허용 |
| **맥북 IP 변경** (DHCP) | 정상 동작 | `.local` 로 접속 중이면 영향 없음. IP 폴백을 쓰던 중이면 실패 | DHCP 예약을 해두면 발생하지 않는다 (9절) |
| **CAROOT 분실** | 정상 동작 | 새 CA 를 만들어야 함 | **태블릿에 CA 를 다시 설치해야 한다.** 그래서 백업이 필요하다 |
| **Pages 장애** | 이미 설치된 기기는 캐시로 정상 동작 | 동일 | 기다린다 |
| **서버 데이터 파일 손상** | 로컬 데이터로 계속 동작 | 백업에서 복원 | 부모 화면의 백업 내보내기를 주기적으로 |

공통 원칙: **어떤 실패도 아이 화면을 멈추지 않는다.** 동기화 실패는 부모
화면에만 드러난다.

## 9. 운영

### 9-1. 공유기 DHCP 예약 (맥북 IP 고정)

`.local` 이름이 되든 안 되든 해두는 것이 낫다. mDNS 가 안 되는 순간
IP 폴백이 유일한 경로가 되는데, 그 IP 가 바뀌면 동기화가 끊긴다.

1. 맥에서 MAC 주소를 확인한다
   `ipconfig getifaddr en0` 로 현재 IP, `networksetup -getmacaddress en0` 로 MAC
2. 공유기 관리 페이지에 접속한다 (보통 `http://192.168.0.1` 또는 `http://192.168.1.1`)
3. **DHCP 예약 / 고정 IP 할당 / Address Reservation** 메뉴를 찾는다
   (제조사마다 이름이 다르다. "DHCP" 로 검색하면 대개 나온다)
4. 맥북의 MAC 주소에 현재 IP 를 고정 배정한다
5. 맥북 와이파이를 껐다 켠 뒤 `ipconfig getifaddr en0` 로 같은 IP 인지 확인

고정한 IP 를 부모 화면의 서버 주소 폴백에 넣어둔다.

### 9-2. mkcert CAROOT 백업

**이걸 잃으면 태블릿에 CA 를 다시 설치해야 한다.** 기기 잠금 PIN, 설정 경로,
보안 경고를 전부 다시 거쳐야 하므로 백업해둔다.

위치:

```
mkcert -CAROOT
# 보통 ~/Library/Application Support/mkcert
#   rootCA.pem      공개 인증서 (태블릿에 설치한 것)
#   rootCA-key.pem  개인키 — 이게 핵심이다
```

백업:

1. 위 폴더를 통째로 **암호화된 곳**에 복사한다 (암호 관리자의 파일 첨부,
   또는 암호화 디스크 이미지). `rootCA-key.pem` 은 이 CA 로 아무 인증서나
   발급할 수 있는 키다. 클라우드 평문 저장은 피한다
2. 공개 저장소에는 절대 넣지 않는다

복구:

1. 백업한 두 파일을 `mkcert -CAROOT` 가 가리키는 경로에 되돌린다
2. `mkcert <맥북이름>.local <맥북IP> localhost 127.0.0.1` 로 리프를 재발급한다
3. 서버를 재시작한다. **태블릿은 손대지 않아도 된다**

### 9-3. 인증서 갱신

리프 인증서는 약 2년 3개월짜리다(2026-09 발급분은 2028-12 만료). 만료되면
동기화만 멈추고 아이 화면은 살아 있다. 9-2 의 2~3단계만 하면 된다.

## 10. 마이그레이션

**불필요하다.** 앱을 아직 실제로 쓰지 않았으므로 보존할 사용자 데이터가
없다. 기존 `kidboard.v1` 키는 버리고 새 구조로 시작한다. 하위 호환 코드를
넣지 않는다 — 쓰지 않을 분기를 남기면 나중에 읽는 사람이 헷갈린다.

저장 키는 `kidboard.v2` 로 올린다. 옛 키가 남아 있으면 무시한다.

## 11. 테스트 전환

| 기존 | 처리 |
|---|---|
| `[0]` 모달 회귀, `[X]` XSS, `[E]` 콘솔 | 그대로 |
| `offline.spec.js` | 그대로 + 오프라인 체크가 큐에 쌓이는지 확장 |
| `update.spec.js` | 그대로 (서비스워커 전략 안 바뀜) |
| `[13]` SW, `[11~12]` 영속성, `[9]` 롱프레스, `[7][8]` 상점·PIN | 유지 |
| `[1]` 홈(아이 2명) | 폐기 → "아이 1명이면 바로 할 일 화면" 으로 개작 |
| `[2]` 요일 필터 | 습관에만 적용하도록 축소 |
| `[3~4][5][6]` 체크·별 | 개작 (별이 계산값) |
| `[15]` 자정 | 개작 (숙제는 이월됨) |
| `[16]` streak | 보류 |
| 단위 17개 | 약 10개 재작성 |

신규로 반드시 필요한 것:

1. **이월 + 상한** — 밀린 숙제 6개가 있어도 아이 화면에 4개만, 오래된 것부터
2. **별 계산** — 완료/취소/보너스/교환을 섞어도 합계가 일치
3. **동기화 멱등성** — 같은 op 를 두 번 보내도 별이 두 배가 되지 않는다
4. **오프라인 큐 유실 없음** — 서버를 죽인 채 체크 3번 → 서버 복구 → 전부 반영
5. **템플릿** — 빈칸을 채워 숙제를 만든다

3·4 번은 `offline.spec.js` 가 쓰는 방식(실제 서버를 띄우고 `SIGKILL`)을
그대로 재사용한다. 이번 갈아엎기에서 가장 값진 자산이 그 패턴이다.

## 12. 아직 정하지 않은 것

- 태블릿이 `.local` 로 접속됐는지 IP 로 접속됐는지 (실기기 재확인 필요).
  설계는 `.local` 우선 + IP 폴백이라 어느 쪽이든 동작한다
- 태블릿 Chrome 버전과 로컬 네트워크 권한 프롬프트 문구 (문서화용)
- 서버 저장 형식 (JSON 파일 vs SQLite) — 구현 시 결정. 가족 규모에서는
  JSON 파일로 충분하고, 백업이 파일 복사라 단순하다
- 숙제 자동 소멸(며칠 지나면 사라짐) — 상한 4개로 화면은 정리되므로 일단
  넣지 않는다. 밀린 것이 실제로 계속 쌓이면 그때 옵션으로 추가한다

## 13. 나중에 집 밖에서 쓰고 싶어지면

맥북에 Tailscale 을 깔고 `tailscale serve` 로 `*.ts.net` 주소를 받는다.
진짜 Let's Encrypt 인증서가 나오므로 **루트 CA 설치와 인증서 만료 관리가
통째로 사라지고**, 사설망이 아니게 되어 로컬 네트워크 권한 프롬프트도
불필요해진다. 앱 출처는 `github.io` 그대로이므로 **모아둔 별은 유지된다.**
바꿀 것은 앱이 호출하는 API 주소 하나뿐이다.
